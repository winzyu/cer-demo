## 3. The judge, and how far it can be trusted

`gpt-oss-120b` (judge) vs `gpt-oss-20b` (under test). Agreement against the 36 human rows, before
and after this session's two fixes:

| dimension | n | exact | within-1 | any/none | **kappa** |
|---|---:|---:|---:|---:|---:|
| correctness | 36 | 83.3% → **91.7%** | 94.4% → **100%** | 94.4% → **100%** | 0.75 → **0.87** |
| ungrounded claims | 36 | 72.2% | 83.3% | 86.1% | **0.46** (unchanged) |
| citation support | 12 | 50.0% → **83.3%** | 91.7% → **100%** | 58.3% → **91.7%** | −0.06 → **0.52** |

**The judge shares a family with the model under test.** §7b's rule ("a different model") is met
as written, not as intended. It was chosen because it is the only non-under-test chat model in
`prices.ts` with a rate read on a known date, and §10 item 4 requires that. `npm run judge` prints
the caveat every run. **This is a stated weakness of every quality number above.**

The two fixes, both corrections *to* the pre-registered definition rather than thresholds moved to
chase a number:

- **Correctness now sees the source documents** when a turn's `must_not` is an invention check —
  25 of the fixtures' 110 distinct `must_not` items (`needsGroundingForCorrectness`). It was
  scoring arms 0 for "inventing" a table row that was verbatim in the source it was not shown.
- **Citation support judges documents, not line ranges.** §8a says "the cited **document** must
  actually contain the claim" and `GRADING_GUIDE.md` §3 told the human the same; the narrow
  line-span reading was the judge's own invention.

**Still open on the judge:** the off-contract-refusal question. The judge scores correctness 1
where the human scored 2, on a refusal that names the missing information but does not use
`REFUSAL_SENTENCE` verbatim. Tier 1 already treats that behaviour as **passing** the refusal gate
(§8b: the gate vetoes on answering, not on wording), so the judge is currently stricter than the
pre-registration. Worth 0.1–0.2 on the arm means.

## 4. Commands

```
npm run gate:check                     # Tier 1. Free, deterministic, seconds. Run it constantly.
npm run judge -- --dry-run             # what a judging pass would cost, without spending
npm run judge -- --calibration         # 6 human-graded fixtures, 3 arms — the agreement sample
npm run judge -- --calibrate           # judge-vs-human agreement, no calls
npm run judge -- --report              # summarize the existing ledger, no calls
npm run judge -- --arm=a,b             # full pass, restricted
npm run cost                           # offline cost model over the dated price sheet
npm run retrieval:eval                 # offline retrieval diagnostics, ~10s, no LLM
npm run grade:packet -- --out=<dir>    # blind human packet. NEVER without --out or --force.
```

**Judge ledger.** Verdicts append to `data/judge/<pass>.jsonl` as they arrive; a re-run skips what
is already there, so an interrupted pass resumes rather than being repaid. **To force a re-judge,
delete the relevant lines.** `data/*` is gitignored, so none of it is committed — see §6.

**Capturing an arm** (only if the system changes; costs money, ~$0.02–0.05 per arm):

```
PORT=8010 SENSOR_TOOL=false REPORT_TOOL=false DEBUG_RETRIEVAL=true \
  CORPUS_SOURCE=firestore DEFAULT_RETRIEVAL=firestore-direct LLM_MAX_TOKENS=16384 \
  npx ts-node src/index.ts

SENSOR_TOOL=false REPORT_TOOL=false DEBUG_RETRIEVAL=true CORPUS_SOURCE=firestore \
  npm run bakeoff -- --arm=<arm> --pass=warm --base-url=http://localhost:8010/api/v1 --spot-check
```

Then drop `--spot-check` for the real sweep. **The user usually has a server on port 8000 with
different env — do not kill it, use another port.**

## 6. Traps — the ones that cost real time

Carried forward and still live:

- **`stub` scores 20.2% recall while retrieving nothing.** 20 of 99 labelled queries are
  `noRelevantChunks` and correctly retrieving nothing scores 1. Every recall number reads ~20
  points better than it is. **It is the floor, not zero.** Retrieval metrics are diagnostics with
  no pre-registered target; an arm cannot pass ◆G7 on them.
- **Unicode breaks exact matching.** The model emits `water‑quality` with U+2011 where
  `REFUSAL_SENTENCE` has U+002D, and **NFKC folds U+2011 to U+2010, not U+002D**. Use
  `src/eval/gates/normalize.ts`'s `normalizeForMatch`.
- **Grounding is wider than the retrieval context.** The system prompt carries the operator normal
  ranges and the question may supply figures. A transcript's `context` field is retrieval context
  ONLY. Treating it as the whole grounding produced ~24 false "fabricated figure" findings per arm.
- **`SENSOR_TOOL=false` must be set on BOTH the server AND the runner.** Server-only gives 30
  fixtures instead of 28 and junk answers.
- **The system prompt is a pinned control until ◆G7 is scoped.** Editing it voids captured arms.
- **Re-chunking invalidates all 259 retrieval labels.**
- **`local-vector` is not a separate arm** from `firestore-vector` (identical ranking, drift ~1e-4,
  Firestore's index is `flat`). `local-hybrid` stands in the same relation to `hybrid-slice-lexvec`.

New this session:

- **`npm run grade:packet` re-labels every answer when the arm set changes.** A 4-arm shuffle
  assigns nothing where the 3-arm one did, so old grades stop describing the answers they were
  written against. The guard blocks it; `--out=<dir>` is the right escape, not `--force`.
- **The calibration subset was optimistic enough to mislead.** `firestore-direct` scored 1.50/2 on
  6 fixtures and **1.08/2** on all 58 — the difference between clearing the floor and failing it.
  A subset calibrates the judge; it does not produce a result.
- **`data/*` is gitignored**, so `data/judge/warm.jsonl`, `data/judge/warm.json` and
  `data/gate-check/warm.json` are **not committed** — yet both reports cite them as evidence and
  §9's exit criteria say grades are committed. **Unresolved; decide it.** Losing that directory
  loses ~$0.9 of verdicts and the audit trail behind every quality number.
- **The user runs a server on port 8000 with its own env.** Use another port for captures.
- Raw agreement is inflated wherever one value dominates — `invalid_citations` is 0 in 33 of 36
  human rows, so an unconditional "0" scores ~92%. **Read kappa, not the percentages.**
