## 2. The finding that should drive the next session

**Retrieval quality is not the constraint, and there is now arithmetic proof that it cannot become
one.** Three measurements, all free, all from transcripts already on disk:

### 2a. The hybrids already carry the whole slice

`hybrid-slice-vector` is `DirectFeedAdapter` + `LocalVectorAdapter` composed. It sends the
**entire** ◆G9 slice unconditionally, then appends five retrieved chunks. On a slice-answerable
question it has everything `firestore-direct` has, and more.

| turns | `firestore-direct` | `hybrid-slice-vector` |
|---|---:|---:|
| 52 slice-answerable | **1.08** | 0.88 |
| 6 needing the manuals | 0.33 | **0.83** |

On the slice-answerable turns the hybrid is worse on **12**, better on 3, tied on 37. **Retrieval
did not "miss" anything on those 12 — the answer was already in the prompt.** The extra chunks
made the answer worse. Per class, `cross-document` (+0.50) and `probe-calibration` (+0.50) suffer
most; `deep-in-manual` is the only class where retrieval wins (−0.50, i.e. hybrid ahead).

**This is context dilution, not a recall deficit.** Raising recall/MRR adds *more* chunks and
should be expected to make it worse. Reproduce with
`python3` over `data/results/judge/warm.jsonl` — the script pattern is in §6.

### 2b. The arm-level ceiling is below the floor

An **oracle router** that picks the best of the three judged arms for every single turn — which no
real system can beat:

| over all 58 judged turns | correctness |
|---|---:|
| `firestore-direct` | 1.000 |
| `hybrid-slice-vector` | 0.879 |
| `hybrid-slice-lexvec` | 0.862 |
| **oracle, best arm per turn** | **1.155** |
| **§8a floor** | **1.300** |

*(computed over all 58 judged turns; §1's 1.08 is over the servable subset — same direction)*

**A perfect router fails the floor by 0.145.** No reranker, no query rewriting, no routing scheme
closes ◆G7's correctness gate with the current generation setup. **Only changing generation can.**

### 2c. 90% of the evaluation is answerable from 4.4% of the corpus

The slice is 37,660 of 851,611 chars. **Only 3 of the 30 registered fixtures need material outside
it**, and all three are `deep-in-manual` — the class `firestore-direct` fails at 0.33/2. So
direct-feed's "wins 8 of 11 classes" is a win on a question mix that is overwhelmingly
slice-answerable. Not rigged — the slice was curated to be authoritative and §8a charges the gap as
coverage — but **the margin is a function of the fixture mix.** Three fixtures is thin for a class
carrying this much weight.

**Mind the two denominators, which are both correct and easy to misread as a contradiction.** 30
fixtures / 62 turns are registered; **28 fixtures / 58 turns are runnable** on the default
`SENSOR_TOOL=false` configuration and are what every captured and judged number here is computed
over. So "3 of 30 need the manuals" and "coverage 89.3%" are consistent: 89.3% is **25 of the 28
runnable**. Coverage is **not a gate** — §8a sets no threshold on it, making it a headline column
and an input to the split-outcome decision only.

**Note the mechanism precisely**, because it is easy to state wrongly: direct-feed does **not**
degrade from being handed a large context. It never sees one — its prompt is a fixed ~9,415
tokens. The whole corpus is ~213,000 tokens and is not feedable by any arm at any price. The
exposure is blindness to the 95.6% it never sees, not dilution within what it does.

## 3. The judge — what it is actually worth

**Correctness is deterministic.** Two identical runs agreed 36/36; five identical runs over the
refusal fixtures agreed 30/30 with a per-arm spread of exactly 0.00.

**The count dimensions are not.** Re-judging with byte-identical prompts changed 11 of 36
`ungrounded` verdicts and 4 of 9 `citations` verdicts. The instability tracks how much text the
judge emits — a score is stable, an enumerated list of claims is not. The gate metric is steadier
than the raw counts it derives from (**86.1%** vs 69.4% reproducible), and on `firestore-direct`
the gate metric reproduced exactly.

**A defect was found and fixed that had inverted a published result.** A grading packet is pinned
to the transcripts it was built from. `firestore-vector` was re-captured 2026-08-26 *after* a human
graded it, so 12 of 36 human rows described answers that no longer existed, and `--calibrate`
joined on `(fixture, turn, arm)` and could not see it. Scored over all 36 rows the refusal fix
looked like a regression (kappa 0.87 → 0.83); over the 24 comparable rows it was 0.81 → **0.94**.

`--calibrate` now compares the packet's stored answer to the transcript and **excludes** rows the
arm has outgrown, printing them before the numbers. Excluding all 12 raised every dimension:

| dimension | over all 36 | over the 24 comparable |
|---|---:|---:|
| correctness | kappa 0.83 | **0.87** |
| ungrounded | kappa 0.33 | **0.57** |
| citations | kappa 0.17 | **0.44** |

**The judge was always better than the report claimed.** A third of the sample was scoring it
against answers it never saw.

**Still true:** the judge (`gpt-oss-120b`) shares a family with the model under test
(`gpt-oss-20b`). §7b's rule is met as written, not as intended. `npm run judge` prints the caveat
every run.

## 6. Reproducing the §2 findings

All free. `data/results/judge/warm.jsonl` holds the full Tier-2 pass; each line is one verdict with
`arm`, `fixtureId`, `turn`, `dimension`, and `score` (correctness) or `count` (the others).

```python
import json
s = {}
for line in open("data/results/judge/warm.jsonl", encoding="utf8"):
    r = json.loads(line)
    if r["dimension"] == "correctness":
        s[(r["arm"], r["fixtureId"], r["turn"])] = r["score"]

arms = ["firestore-direct", "hybrid-slice-vector", "hybrid-slice-lexvec"]
turns = sorted({(f, t) for a, f, t in s if a in arms})
rows = [(f, t) for f, t in turns if all((a, f, t) in s for a in arms)]
oracle = sum(max(s[(a, f, t)] for a in arms) for f, t in rows) / len(rows)
print(len(rows), oracle)          # 58, 1.155 — the ceiling, against a 1.300 floor
```

Slice membership comes from `data/corpus/corpus.json` → `documents[].inDirectFeedSlice`; a fixture
needs the manuals when any entry in its `answerable_from` is not a slice document.

## 7. Dispatching agents — the protocol, then two briefs

Generation and retrieval can be worked **in parallel**. They are separable in code and the whole
combined evaluation costs under a dollar. Three rules make it work; breaking any one of them costs
money or produces an uninterpretable result.

### 7.0 The protocol

**Rule 1 — non-overlapping ownership, enforced.**

| | **Agent A — generation** | **Agent B — retrieval** |
|---|---|---|
| owns | `src/prompt/systemPrompt.ts`, `src/eval/gates/`, `test/unit/{prompt,gateCheck}.test.ts` | `src/retrieval/**`, `test/unit/{hybridSliceVector,localVector,rrfHybrid}.test.ts` |
| goal | ungrounded turns 53% → ≤2%; correctness 1.08 → ≥1.30 | close the 0.20 dilution gap, keep ≥0.83 on `deep-in-manual` |
| free signal | `npm run gate:check` | `npm run gate:check`, `npm run retrieval:eval` |

`src/prompt/systemPrompt.ts` is **A's alone.** B will be tempted — "mark the slice as
authoritative" is a prompt change — and must write the proposed wording into `docs/notes/` rather
than edit the file. Both are barred from `RETRIEVAL_COMPARISON.md`, `RETRIEVAL_BAKEOFF.md` and
`timeline.md`; one integrator folds their notes in afterwards.

**Rule 2 — neither agent captures or judges.** Both iterate only on the free deterministic
signals. Captures and judging happen **once, at the end, run by the user**. This is what makes
parallel work cheap: otherwise each agent burns ~$1 per iteration, twice over, on changes that
interact.

**Rule 3 — de-confound with one factorial cycle.** The two changes are not independent *in
effect*: a prompt that suppresses unsupported claims may also suppress the distraction causing the
dilution gap. Capturing only the combined system leaves you unable to attribute a move. Capture
four cells instead:

| | old retrieval | new retrieval |
|---|---|---|
| **old prompt** | baseline — already captured | B alone |
| **new prompt** | A alone | A + B |

Three new captures at ~$0.02–0.05 each, judged at ~$0.22/arm ≈ **$0.75 total** — less than one
blind combined cycle would cost to redo.

**One asymmetry to respect.** A has 28 fixtures of signal and is working on the only thing that
can open the gate. B has **3** — the whole `deep-in-manual` class — and is working on something
that provably cannot (oracle 1.155 vs floor 1.300). B is real work with a real pre-deploy
justification; it is the junior partner and must not set the schedule.

  ONLY. Treating it as the whole grounding produced ~24 false "fabricated figure" findings per arm.
- **`SENSOR_TOOL=false` must be set on BOTH the server AND the runner.** Server-only gives 30
  fixtures instead of 28 and junk answers.
- **Re-chunking invalidates all 259 retrieval labels.**
- **`local-vector` is not a separate arm** from `firestore-vector` (identical ranking, drift ~1e-4,
  Firestore's index is `flat`). `local-hybrid` stands in the same relation to `hybrid-slice-lexvec`.
- **`npm run grade:packet` re-labels every answer when the arm set changes.** Use `--out=<dir>`,
  never `--force`. It destroyed 36 completed grading rows once.
- **The calibration subset is optimistic.** `firestore-direct` scored 1.50/2 on 6 fixtures and
  1.08/2 on all 58. A subset calibrates the judge; it does not produce a result.

New this session:

- **A grading packet is pinned to its transcripts.** Re-capturing an arm silently invalidates every
  human row for it. `--calibrate` now detects and excludes those rows — but the *data* problem
  remains until the arm is re-graded, and it inverted a published result before the check existed.
- **`Date.now()` is not a clock for measuring elapsed time.** It is civil time and the OS may step
  it backwards, which is where the negative `ttftMs` came from. `src/eval/transport.ts` now uses
  `performance.now()`. **The fix is not retroactive** — old transcripts stay unusable for latency.
- **`npm run typecheck` only covers `src/**/*`.** `scripts/` and `test/` are not typechecked; they
  are validated by eslint and by actually running them. A clean typecheck says less than it looks.
- **The judge's list-producing dimensions do not reproduce** (§3). Never rest an argument on
  per-arm *differences* in the groundedness column.
- **Adding a rule to a judge prompt is not free where it does not apply.** An unconditional refusal
  rule changed verdicts on unrelated turns; scoping it to refusal turns cost a row and was
  reverted. Rules compete for the judge's attention on every turn they appear on.
- **`npm run cost` holds completion length constant by design.** Use `--completion=measured` to
  reproduce §1. The two views answer different questions and both are correct.
